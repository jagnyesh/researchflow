- ECC `continuous-learning-v2` · copy-a-folder pinned @ `d2ef268` (full `d2ef2680594f9a17526a6e1a2e18b3d242c5d17b`; github.com/affaan-m/ECC, maintained by GitHub user `affaan-m`, 847 upstream commits after the pin on 2026-11-21) plus a local patch · 2026-11-21 · **PASS for the sandbox pilot only (gap 3 of the harness gap plan), with the patch.** Not installed as a plugin, a skill (no `SKILL.md`), or through ECC's installer. §5.5: a static read of all 12 files in the folder (6,509 lines) found nothing malicious or obfuscated: no base64, no eval of fetched content, no `curl | bash`. The only network call is the manual `instinct-cli.py import <https-url>`. Then a canary test on Claude Code 2.1.330 in a throwaway folder. **As shipped, the analyzer (`agents/observer-loop.sh:399`, `claude -p --allowedTools "Read,Write"`) is not contained:** a prompt that asked for it wrote files outside the repo, in the repo root and in the parent folder, and read a secret file into its output, which the loop appends to `observer.log`. It also connected to every MCP server in the user config. The prompt-ordered writes to `.claude/settings.json` and `~/.claude/settings.json` were refused even as shipped. **The patch, `docs/audits/ecc-clv2/clv2-local.patch`, changes four files:**
  - The analyzer gets `--setting-sources "" --no-session-persistence --permission-mode default --tools "Read,Write,Edit" --allowedTools "Read(/<project dir>/**)" "Edit(/<instincts dir>/**)" --strict-mcp-config --disable-slash-commands`. It also refuses to run when `PROJECT_DIR` or `INSTINCTS_DIR` is empty, because an empty value would turn the rule into `Edit(//**)`. With these flags the same canaries wrote only to the instincts folder, leaked nothing, and made no MCP connections.
    - The two flags at the front came from the fresh-context review. Without `--setting-sources ""`, a bare `Read` allow in the sandbox repo's `.claude/settings.local.json` let the analyzer read a secret outside its folders. That file is the one the installer writes, and it's where "don't ask again" grants land. An allow rule passed through `--settings` widened it the same way, so an allow rule in the user's `~/.claude/settings.json` would too (not tested, to keep `~/.claude` untouched).
    - Without `--no-session-persistence`, each `-p` run saved its transcript, observation content included, under `~/.claude/projects/`, outside the sandbox and untouched by the purge or the uninstall.
    - Both fixes were re-tested: with `Read`, `Edit` and `Write` allowed in `settings.local.json`, reads and writes outside the folders were still refused, and no analyzer transcript was saved.
  - `session-guardian.sh` would otherwise write `~/.claude/observer-last-run.log`. `observer-loop.sh` now exports `OBSERVER_LAST_RUN_LOG` in the project's data folder; `session-guardian.sh` itself is unchanged.
  - The `.observer.lock` sentinel moves out of the repo tree.
  - Every inline `python3 -c` and `python3 -` gets `-I`, so a planted `json.py` in the working folder doesn't run on each tool call. `umask 077` is set too.
  - The secret scrubber gains bare `sk-ant-`, `sk-`, `sk_live_`, `xox?-`, `AIza`, `npm_`, `hf_`, `glpat-` and JWT patterns, and the `passwd`, `pwd`, `cookie` and `session` keywords. The value length cap becomes 8,192 for keyword values and for `ghp_` tokens, above the hook's 5,000-character truncation. Every leak shape found in the read and the review was redacted after the patch, and pathological inputs scrub in about 1 ms. It still over-redacts the word after `token ` or `auth `, which is the safe direction.
